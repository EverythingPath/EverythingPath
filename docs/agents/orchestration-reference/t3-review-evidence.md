# T3 review evidence: binding policy and evidence inventory

Reference for [T3 review evidence](../orchestration/t3-reviews.md): the original-message policy the bridge enforces and what each binding checks and keeps. Read it when a bind or completion refuses, or before changing `scripts/catalog/t3-review-bridge.ts` (started through `start-without-tsx-cache.mjs`), `t3-review-code-mode.ts` or `t3-review-evidence.ts`.

## Original-message policy

New bindings use `t3-review-dispatch-v3`, selecting local **review-role-v1**: for frozen `request.role = "review"`, the complete original text must equal the literal `Act as the review sub-agent for this task.\n\n` prefix (two LF characters), followed by the entire unchanged `request.task`. This exact 44-code-unit prefix was observed during #766's 2026-10-23 authentic qualification; the saved original was 4,690 code units and the frozen body 4,646. The regression observations are documented in [the fixture provenance](../../../tests/fixtures/review-766/README.md). This is a versioned local adapter policy, not a versioned server guarantee or an outer-role API echo.

Current binding accepts that one representation. Changed/repeated wrappers, arbitrary preambles, bare bodies, whitespace changes and role/payload/manifest/nonce mismatches reject. Equality compares the whole expected representation once; it never searches for or strips a prefix. Original-message/run/parent/origin checks still apply before equality. Full raw decorated text and observations are archived unchanged and hashed; completion, recording and historical verification replay the policy selected by the binding kind.

Archived `t3-review-dispatch-v2` bindings retain their original exact bare-task equality rule, solely for historical replay. They gain no wrapper support; new binding never emits v2. Existing capture/completion formats and receipt hashes remain unchanged. Never rewrite an old binding, reclassify a failed attempt or manufacture retrospective correlation evidence. Uncorrelated v1 remains rejected. All existing bounds remain, including the 16,000-code-unit **total recovered message** bound (the wrapper counts toward it).

## Evidence checked and retained

- API-observed: dispatch/status task, child node/thread and original run; effective provider/model/options; terminal/pending-work state. Every expected option must appear exactly once with the same value.
- Dispatch return: the operator's direct `delegate_task` return (recorded 2026-11-20: code mode has no `delegate_task`), supplied to the helper's bind. It authorizes nothing alone: a nested `isError` refuses; its provider/model/options must equal the captured target and, unless saved, its status must not be failed, cancelled or interrupted; actual `task_status` for its `taskId` must show the same task, child thread and node and its original run (or the return's run is null); and the original message read must bind. Bind's rules, in order:
  1. The supplied input is validated (the raw entry point also refuses an unparsable status or missing reads).
  2. A round with `completed.json` as bind starts is refused, with no write.
  3. When, as bind starts, the saved return's bytes are the bytes bind writes for the supplied one and `dispatch.json` is an intact binding that names its hash (intact means byte-equal: the saved return must be the bytes bind writes for the supplied return, and `dispatch.json` the canonical form bind writes for what it parses to, final newline included), bind is success before any T3 tool call, with no write.
  4. Any other `dispatch.json` (a binding of another return, one whose bytes are not the canonical form, an invalid one, or one that another bind of the same return published after this bind found no saved return) is refused, with no write.
  5. Otherwise the live checks run on the return and reads this attempt transported (below), then `dispatch-return.json` is written directly into the round with an exclusive create, which fails if the name exists (equal bytes carry on, different ones refuse), `completed.json` is checked again, and `dispatch.json` is written the same way, a failed create being success only if the binding there names this return's hash.

  After any refusal, bind once more with the same return; a second refusal means the round is abandoned and captured anew ([abandon the round](../orchestration/t3-reviews.md)), unless the child is still queued or has pending work, or the round is completed. Bind creates no temporary file in a round, and nothing at any path derived from a round's path: its only writes there are the exclusive creates of `dispatch-return.json` and `dispatch.json` inside the round (the final mode 0444 set on the open descriptor before the first byte, then write, flush, close; no mode, owner or time is changed by path), and a completed round has both, so bind can no longer create, change or remove anything in a completed round's directory. A write interrupted part-way can leave a file short of the bytes bind writes, which fails closed: such a `dispatch-return.json` is not byte-equal to the supplied return and such a `dispatch.json` is not an intact binding, so bind declines, completion refuses that binding, and the round is abandoned. Transport files (the return and the reads a bind attempt hands its later bridge steps outside the bounded payloads) are each in a private directory made by the step that writes it with `mkdtemp` in the system temporary directory, once bind has checked the system temporary directory as every round command does: every round command (the record step's `--capture-t3`, `--bind-t3`, `--complete-t3`, `--t3-run` and `--verify`, and every bridge action) declines, naming `TMPDIR`, before it writes anything, a system temporary directory whose real path is, is inside or contains the round it operates on (the round directory it is given, capture's new one included; for `--verify`, each archive it verifies), and nothing is inferred from file names elsewhere (`requireTemporaryDirectoryOutside` in `scripts/catalog/t3-review-evidence.ts`); the launcher, `scripts/catalog/start-without-tsx-cache.mjs`, is the documented way to start each (started without it, tsx writes its disk cache under the temporary directory before the command can check that directory), and started any other way each runs as before; no other program declines a `TMPDIR` at a round, so do not point it at one; a later step reads only the directory it is handed in its own call (any other path is refused), and the attempt removes them, best effort: a failed removal, or a reply lost before the attempt learned the path, leaves the private directory behind, and nothing reads it.

- Independently API-observed: first original local child user message, item/message/run IDs, sender/source thread, `agent`/`mcp` origin and subagent parent lineage. Reads start at the beginning, advance timeline cursors and reconstruct UTF-16 text offsets with stable item/lineage metadata. Inherited/synthetic content, assistant quotations, later steering/runs, missing evidence, ambiguous/truncated/stalled recovery and bound exhaustion reject. The recent-run window is not treated as complete history.
- Locally declared/requested: author provenance and outer `role`, `title`, retry key, isolation and mode. Their manifest entries prove those declarations reached the task body, not that the server interpreted those outer arguments. Neither status nor thread reads echo those received outer arguments. Opaque IDs are compared literally, never decoded.
- Durable preservation: full recovered text and raw read arguments/responses, immutable snapshots, dispatch return, binding, terminal status, full report and completion hashes. Completion, recording and every historical verification replay the archived original-message association. The committed report copy must be byte-identical. Historical verification works offline after child-thread or disposable-checkout cleanup; it does not require an undeleted live task forever.

These are writable local artifacts controlled by the orchestrator, not cryptographic attestation of execution or authorship. A determined actor rewriting every artifact and receipt remains outside this boundary. No global nonce registry, scheduler or new trust principal is introduced. Preserve original failures and never represent synthetic fixtures as authentic execution qualification.
