# Standing owner decisions

These bind every orchestrator and worker until the owner changes them. Owner records are `$EP_ORCH/mvp-20261023/owner-decision-<date>-<topic>.md`; record a new decision here as one line with its date and a pointer.

## Workflow

- **Instructions (2026-10-08):** all workflow instructions live in the repo: `docs/agents/orchestration.md`, this folder and `scripts/orchestration/`. `$EP_ORCH` holds only run state.
- **Models and runtime (2026-10-27):** the [overlay role table](../orchestration.md#roles-and-models) is the current selection; coding work uses T3 worktrees with the shared `EP_ORCH`. Retain actual historical model/options and receipt formats; historical receipts keep their actual identities.
- **Authorization and failures (2026-10-27):** apply the runbook's explicit support boundary, delta review and evidence reuse procedure. Authorizing a run authorizes its specified successful local phase transitions once. Ordinary diagnosed implementation or fixture failures may be fixed and checked at the affected seam in the same task, without a new worker or parent permission handshake; a safe setup omission before any child launch may be corrected in-task with proof that nothing launched. Live gate failures and resource or observer safety events keep their evidence and need diagnosis before a fresh attempt; OOM never triggers an automatic retry. Full original-suite all-green, admission and promotion receipts and checked landing stay required.
- **Fix rounds:** no numerical cap; [runbook §7](runbook.md#7-fix-round).
- **Resources (2026-10-29, workers 2026-10-30):** `$EP_ORCH/resource-policy.md` is the source; read it before scheduling. All locks, caps, heaps, timeouts and the admission budget stay.
- **Remote heavy checks (2026-10-30):** a verified Boat manifest for the exact tree may replace or be compared with the local typecheck, lint and full suite: [remote heavy checks](operations.md#remote-heavy-checks).
- **Rebase-only reviews (2026-10-31):** a mechanical rebase of accepted work keeps its reviews: [mechanical-rebase proof](operations.md#mechanical-rebase-proof).
- **Single-axis fix reviews (2026-10-31):** when only one axis had findings, only that axis re-reviews: [single-axis fix review](operations.md#single-axis-fix-review).
- **Light landing lane (2026-11-01):** skip full gates when provably unnecessary, on a bounded-risk basis: [light landing lane](operations.md#light-landing-lane).
- Default gates are unchanged by these four modes. Pairs are excluded from all four; curation from the rebase proof, single-axis review and light lane.
- **No blocking on owner questions (2026-11-03, `owner-decision-20261103-no-blocking-questions.md`):** "If it's the middle of the night I don't want you to get stuck like this again waiting for an answer instead of working towards finishing the MVP." Root never ends a turn with nothing in flight because an owner question waits: it decides reversible choices within its authority and records them, parks owner-only ones (publishing, notice or legal text, destructive actions, #413's production steps (narrowed 2026-11-10, below), spending, changing an owner decision) and continues. When nothing is unblocked, it says so in one message.
- **Never idle on a wait (2026-11-05, `owner-decision-20261105-no-idle-waiting.md`):** "i want you to consider things like these instead of waiting around doing nothing". When root is blocked on a wait (the memory guard, a quiet window, a storage stop, a slow reviewer), it switches route at once instead of idling: remote CI with a `replace` gate, lending the idle host to another thread while CI runs, or unblocked parallel work within the concurrency and disjoint-files rules. A "waiting" report names what else is moving, or why nothing can. No safety rule loosens. The debt cap (2026-11-10, below) narrows this for coding slots.
- **Gate-time review (2026-11-08, `owner-decision-20261108-gate-time-review.md` §2; from the next gate):** "any increase in gate time over 30% must be reviewed"; corrected the same day: "There should not be a queued speed task, the gate should fail." The measure is the gate's own work time: CI's critical path (the longest job's execution, `startedAt` to `completedAt`) plus the host gate's phases, without admission or lock waits. The baseline is the median of the last five landed gates of the same mode (replace, local/compare, curation). The trigger is more than 30% above it: root records the increase in the gate result and checks why before landing. Outside causes (slow runner launch, CI queueing, GitHub incidents, host contention, retries) don't count: note them and move on. An increase the item caused (new or heavier tests, extra setup, a slower step) fails the gate: the item gets a fix round that brings its gate time back under the trigger, then gates again. The gate checks this itself and refuses on a trigger (gate-time-check, [gate time](operations.md#gate-time)); root records an outside cause in the spec's `gate_time_exempt`. Example: a70e1440 took gate CI's static job from 6.6 to 19.9 min.
- **Deployment boundary:** the campaign target is Convex Cloud production, but setup and implementation authorize no Cloud operation. Checks stay local unless separately authorized.
- **GitHub (D1, 2026-11-01; extended 2026-11-04):** comment on each issue as it lands. No PRs and no closes. The integration branch stays local; frozen landing candidates, and commits frozen for review, may be pushed to `origin` as `gate/<label>` so CI runs the heavy checks.
- **CI at review freeze (2026-11-04, `owner-decision-20261104-review-freeze-ci-conditional-land.md`; extends D1):** a commit frozen for review may be pushed to `gate/<label>` as the tree-only gate commit right away, so CI runs during the reviews. Only green CI on the exact final tree authorizes landing: a fix round, a rebase onto a moved base or any other tree change needs a fresh run, and pending or failed speculative CI never authorizes landing. Procedure: [runbook §6](runbook.md#6-reviews) and [§10](runbook.md#10-land).
- **Conditional LAND (2026-11-04, same record):** a reviewer may answer "LAND once X is fixed" when X can be checked mechanically (for example stale counts or a commit message). The orchestrator verifies X and records the check, with no further review round. A repair that is not machine-checkable, or a fix that goes beyond X, gets an ordinary fix-round review. Standards and Spec stay separate reviews; the owner declined a combined reviewer. Procedure: [runbook §7](runbook.md#7-fix-round).
- **Fewer fix rounds (2026-11-07, `owner-decision-20261107-fewer-fix-rounds.md`):** guards state a threat model, round 1 is complete and fix rounds are delta-only, only blockers and hard violations block (narrowing single-axis fix reviews), docs come last, and reviewers may use WIP CI: [`roles/common.md`](roles/common.md), [`roles/reviewer.md`](roles/reviewer.md).
- **Stop lifted (2026-11-10, `owner-decision-20261110-stop-lifted.md`):** the "no new starts" stop of 2026-11-10 ended that night; work follows the decisions dated 2026-11-10 below.
- **Debt cap (2026-11-10, `owner-decision-20261110-debt-cap.md`):** at most one of the three coding slots runs debt or tooling work at a time, and that item's fix rounds and rebases count against the same slot. Debt is dispatched only when it unblocks or speeds up met work (a landing, a gate, a curation wave, a recurring stall); optional cleanups are queued, unless they ride along in a slice already touching the file. When no met-bearing code item is unblocked, the slot stays idle and Now says so ("slot N idle: no unblocked met work"). This narrows "Never idle on a wait" for coding slots only; curation, reviews, gates and CI still never wait idle. Landing finished, reviewed debt takes no coding slot.
- **#413 code (2026-11-10, `owner-decision-20261110-413-code-and-la-status.md` §1):** #413 code and isolated integration tests are dispatched like other implementation work; this narrows the #413 entry of "No blocking on owner questions" to production steps. Deploying, production activation, the cutover rehearsal on Cloud data (#714), legacy cleanup (#715) and any new purge or retention policy each need their own owner go-ahead. The first step is a read-only check that #327 and #319 are on the integration branch, then a slice plan shown to the owner before any code. Slices that share Convex files with builder work run one after another.
- **Progress by launch criterion (2026-11-10, same record §2):** Now carries one line per launch criterion LA1-LA10 of #767 with its state and blocker. The `pnpm -s mvp:status` row count is the evidence behind LA1 and LA3, not the headline.
- **Verification (2026-11-10, `owner-decision-20261110-verification-four-changes.md`):** four changes, approved 2026-11-10; each is a worker slice with Standards and Spec review through the normal gate, and until a change's slice lands, the current check applies. (1) Generated scope files refer to records by stable key instead of by position (`{"$record": N}`), so a wave touches only its own rows. (2) A green CI run on the candidate commit proves a family's tests hold, in place of the SHA-256 byte pins of test files and of the calculator in the mechanism proof registry; the registry still names its tests, and the gate checks that they ran and passed on the candidate. (3) Zero-difference rows are held ([curation lane](#curation-lane)). (4) A read-only audit of every receipt, attestation and input file the gate requires, then removal of those that have only ever failed on themselves. The audit and a design note for (1) come first, and (2) follows (1). CI still runs the full suite on every landing, and no row counts as met without real evidence (2026-11-03).
- **Line count (2026-11-10, `owner-decision-20261110-line-count.md`):** the history snapshots under `tests/fixtures` (`preserved.json`, `protected-context.json`, `original-identities.json`, `local-binding-proof.json`) may be removed ahead of curation completion, the snapshot part of #744 only; the per-batch fixture loaders still import them, so removal is a worker slice with review and the normal gate. Approved 2026-11-10; until that slice lands, the snapshots and their loaders stay. A read-only design slice for storing each text of the legal assessment records once, referred to by hash, is held until the #227 admission rule is in the contract ([launch and admission](#launch-and-admission-2026-11-10)); it delivers a proof that the compact form expands to the same content and a statement of which assessment bindings and fingerprints move, and its implementation needs the owner to see the design first. Both are debt that speeds landings under the debt cap, the snapshot removal first.
- **Threat model (2026-11-11, `owner-decision-20261111-413-plan-guard-prose-threat-model.md` §4):** "our own workers are not malicious actors so we only need to protect against mistakes." Guards, gates and reviews protect against mistakes by cooperative workers on every kind of code, admission, notices and release state included; a finding blocks only if a plausible mistake produces it, and one that needs a deliberately constructed input or sequence is a nit: [`roles/common.md`](roles/common.md), [`roles/reviewer.md`](roles/reviewer.md).
- **Delete what is unused (2026-11-12, `owner-decision-20261112-workflow-plan-parallel-curation-delete-unused.md` §3):** "anything unused should be deleted": unused code, scripts, gate inputs, flags and docs in the workflow are removed outright, not kept as a fallback. Things that hold unlanded work (parked branches, old worktrees, kept evidence) are deleted only after the owner has seen the list.
- **Content:** no made-up test cases or seeds; use published content, or homebrew a player can create in the app. Run a research check before review or coding on rules work, and a targeted example check before drafting issue text.

## Curation lane

- The curator is the curation selection in the [overlay's role table](../orchestration.md#roles-and-models), and a reviewer samples each batch; an admission on a declared book gets no admission review, only the #227 rule's exceptions do; an admission with no declared book gets one until the scripted name match lands ([launch and admission](#launch-and-admission-2026-11-10)).
- **Zero-difference rows (2026-11-10, `owner-decision-20261110-verification-four-changes.md` item 3):** approved but held until the #227 admission rule is in the contract, which makes it mostly unnecessary. Once released, rows where the comparison script finds no differences are admitted on its result: the curator reads only rows with differences, the reviewer reads those in full and samples the rest, and notice and mapping checks no script covers stay with the curator. Until then every admission is reviewed in full.
- Batches run typecheck, lint, the writer check, `catalog:pin`, the gates and their own tests. The orchestrator's post-rebase triage is the landing gate.
- Briefs require the shared Situations and must not break full-corpus `catalog:curate`.
- Record-level `3.5` tags are held, never excluded (2026-10-08).
- Trailing whitespace in notice keys is normalized: the text is stored trimmed, so `sha256(notice)` equals the key (2026-10-08).

## Hygiene

- **TMPDIR** is `<repo parent>/.ep-tmp/<run-id>` (`~/repos/everythingpath/.ep-tmp/`), never `/tmp` and outside every checkout: tests write scripts into it that run as ESM under the repo's `"type": "module"`. The orchestration scripts make one per run and remove it; a worker started without one makes its own there.
- Worktrees hold only `.env.example`; `.env*` files and `e2e/.private` are never read. The owner's uncommitted files and the shared stash stay untouched.
- **Machine load:** one heavy job at a time while the owner is using the machine.
