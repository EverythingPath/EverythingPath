## Rule values

A **rule value** is a number a Catalog Entry gives that is not a Modifier, such as Channel Energy's dice. Each kind has its own combining rule, so none of them goes through [stacking](stacking.md). A Catalog Entry lists them in `ruleValues`; an entry stored before they existed has none and reads as before (`convex/characterSheetRuleValues.integration.test.ts`).

```ts
type RuleValue =
  | { kind: 'dice'; die: number; amount: RuleValueAmount; key?: string } // Channel Energy: d6
  | ({
      kind: 'diceIncrease';
      key: string;
      amount: RuleValueAmount;
    } & IncreaseFields) // the Phylactery of Positive Channeling: 2
  | {
      kind: 'damageReduction';
      amount: RuleValueAmount;
      bypass: string; // '-' is DR x/—; 'cold iron', 'magic' …
      condition?: { situation: RuleValueSituation };
    }
  | {
      kind: 'spellResistance';
      amount: RuleValueAmount;
      condition?: { situation: RuleValueSituation };
    }
  | {
      kind: 'dailyMaximum'; // per-day maximum (owner 2026-11-17)
      key: string; // the Foundry tag: 'classFeat_rage', 'classFeat_channelEnergy' …
      unit: 'uses' | 'rounds' | 'points';
      amount: RuleValueAmount;
      joins?: true; // rotation-6: adds to another maximum of its key and unit
    }
  | ({
      kind: 'dailyMaximumIncrease';
      key: string;
      amount: RuleValueAmount;
    } & IncreaseFields); // Extra Channel

type IncreaseFields = {
  oncePerSource?: true; // rotation-6: copies of one Source add once
  choice?: [string, ...string[]]; // rotation-6: adds only for one of these saved choices
};

type RuleValueSituation = SituationKey | { local: string }; // no option Situation

type RuleValueAmount =
  | number // a whole number, 0 or more
  | { rows: { per?: number } } // the entry's active rows counted, times per (1)
  | { formula: string }; // the closed formula grammar, as a Modifier's
```

The schema is `ruleValueSchema` (`src/lib/character-sheet.ts`). The stored Catalog Entry (`convex/schema.ts`) carries it; the imported entry (`importedCatalogEntrySchema`) carries `storedRuleValuesSchema`, nonempty, and a release's candidate definition takes it from the imported entry. A Catalog Copy carries it through its spread.

**Limits.** Convex's storage validator is derived from the schema and keeps only its types, so every write that stores rule values parses them: `createOneOff` checks them beside its Modifier and Situational Note limits ("An entry supports at most 16 Rule values", "Rule value is invalid"), and `writeCatalogDefinition` parses `storedRuleValuesSchema` ("Catalog definition is invalid"). Release staging (`catalogRelease.writeBatch`) stores a definition row and a retirement report's last usable definition without `writeCatalogDefinition`, so it parses both through `importedCatalogEntrySchema`'s field (`convex/catalogRelease.integration.test.ts`); discovery and candidate reads parse the same schema. At most 16 per entry; a formula of at most 4096 characters, a bypass of at most 64, a per-day or dice key of at most 64, an increase's `choice` of 1 to 16 options of 1 to 64 characters each with a character other than a space, and a Situation as a Situational Note's. Each limit's reason is beside it in `src/lib/character-sheet-feature-numbers.ts`. A one-sided die, a fractional or negative amount, `rows.per` 0, an empty bypass, an empty or over-long per-day or dice key, an unknown unit, and any field outside the kind (a tally of uses, an increase's unit, a dice increase's own die or condition, and since rotation-6 `oncePerSource` or `choice` on a kind that is not an increase, `joins` on a kind that is not a per-day maximum, either flag with a value other than `true`, and an empty, blank, over-long or 17-option `choice`) are refused (`convex/characterSheetSpeedMaxima.integration.test.ts` for the per-day kinds, `convex/characterSheetArmorNoneDice.integration.test.ts` for the dice key and increase, `convex/characterSheetIncreaseRules.integration.test.ts` for the rotation-6 fields, each through `createOneOff` and `writeCatalogDefinition`; `src/lib/character-sheet-dice-increase.test.ts` and the rotation-6 tests below for the imported schema and the curation output, `tests/catalog/rule-value-curation-rotation-6.test.ts` for a rule-value record); an unsupported but well-formed formula is stored and warns when evaluated (`convex/characterSheetRuleValues.integration.test.ts`).

### Amounts

- **Rows:** the entry itself plus each counting entry whose `detail.parentFeature` is the entry's rule identity and that the entry's own class granted (rotation-4): the class's reviewed increments, such as the Cleric's Channel Energy rows at 3rd, 5th … 19th level. A row an Archetype replaces is dormant and a row switched off is not counting, so neither is counted: an Ecclesitheurge Cleric 5 channels 2d6, not 3d6. A parent entry two classes share (the Barbarian's and the Bloodrager's Damage Reduction) counts each class's rows apart: a Barbarian 10 / Bloodrager 10 has two 2/— lines and DR 2/—, not 3/—. A row's class is the class whose Class Level granted it, through nested grants, or the class of the Archetype that added it; an entry no class granted counts only rows no class granted (`src/lib/character-sheet-resistances.test.ts`).
- **Formula:** evaluated as a Modifier on an internal dependent-stage target, so it reads the variables a Modifier reads (`@classLevel.paladin`, ability modifiers, `@bab`), and a Spell Effect's reads its recorded caster level as `@casterLevel`, as that effect's Modifiers do: the spell spell resistance's `12 + @casterLevel` at caster level 9 gives SR 21. A class feature's has no caster level to read. A formula that can't be evaluated gives no number and a rules warning on the entry (`<entry>:ruleValue:<index>`).
- Each amount is evaluated by `evaluateModifier`, so an entry a condition suppresses gives nothing.

Rule values come from the same counting entries as Modifiers; the permanent projection leaves out Temporary Effects.

### Dice

`resolveFeatureNumbers` (`src/lib/character-sheet-feature-numbers.ts`) gives `calculated.featureNumbers`: one feature number per dice rule value of a counting entry, `{ kind: 'dice', entryId, ruleValueIndex, count, die, sources }`, with `increases` and `notCounted` when they apply. `count` is null while its formula can't be evaluated; `sources` names the rows counted, or the entry for a number or formula. Two classes' dice stay apart: a Cleric 5 / Paladin 4 channels 3d6 as a cleric and 2d6 as a paladin, never 5d6.

**Dice increases** (rotation-5). A dice rule value may carry a `key` (the Foundry tag, as a per-day key), and a `diceIncrease { key, amount }` on another counting entry adds its amount to every dice value of that key, in that value's die. The examples in this section are test fixtures (`src/lib/character-sheet-dice-increase.test.ts`): no committed record gives a dice value a key or gives an increase yet ([Which entries carry rule values](#which-entries-carry-rule-values)). A Cleric 8 holding the Phylactery of Positive Channeling (`+2d6`) channels 4d6 + 2d6 = 6d6.

- **Per copy or item:** each counting entry with an increase of the key adds once, unless the increase counts once per Source or is for a choice ([Increases](#increases-once-per-source-a-choice-not-counted-rotation-6)); an item switched off is not counting, and a suppressed entry gives none. `sources` names the dice's rows or entry, then each increase's entry, and `increases` (fix r1), present once any adds, gives each one's `{ entryId, name, count }`: the row shows each beside the total as its own chip, "+2d6 from Phylactery of Positive Channeling".
- **Once per entry, never its own dice** (fix r1): "per copy" is per active copy of the increasing entry (two copies of a feat taken twice), never per line, so one entry's rule values repeat no `diceIncrease` key (two increases of one key on the same entry are refused; increases of one key on different entries, or on independent copies of one entry, each add); and an increase raises another entry's dice, so none names a key its own entry's dice carry. Both are refused at write, never ignored: `storedRuleValuesSchema` (so `writeCatalogDefinition`, release staging, discovery and candidate reads through the imported entry schema), `createOneOff` (`validatePersonalAdjustment`, naming the reason) and a rule-value record (`scripts/catalog/curation.ts`, naming the reason). Increases of two keys on one entry (the Phylactery's), or a `dailyMaximumIncrease` and a `diceIncrease` of one key, are stored.
- **Apart per key:** a Cleric 5 / Paladin 4 with an increase of the Cleric's key alone channels 5d6 and 2d6.
- **No key, no increase:** a dice value without a key is exactly as before. An increase is evaluated only while an unsuppressed keyed dice value of its key is on the sheet (fix r1), so one with none gives nothing and no warning, whatever its formula (a holder with no channel is a valid sheet).
- **Suppressed:** an increase whose entry a condition suppresses (a Grappled Condition that Pinned replaces) is never evaluated: its formula gives no warning and the dice read as without it (fix r1). So is a keyed dice value whose entry a condition suppresses: suppression is decided before its formula, so it gives no number, warns nothing even with a formula that can't be evaluated, and is no match for an increase of its key (fix r2). A dice value without a key is evaluated as before.
- **Unresolved:** an increase whose formula can't be evaluated adds nothing and has its own rules warning on its entry (`<entry>:ruleValue:<index>`); the dice keep their count and sources as without it, with every other increase that counts added to a resolved base (fix r1). With every once-per-Source copy of a Source unresolved, the first of them counts and adds nothing, so an unresolved once-per-Source group adds no dice; a resolved base still receives the other increases that count under the usual rules (once per Source where marked), and each copy warns, the others listed as not counted (rotation-6 fix r2; in a fixture a 1d6 base with two unresolved copies of one Source and an independent +2d6 gives 3d6, fix r4; `src/lib/character-sheet-increase-once-per-source.test.ts`). An increase whose entry is suppressed, or that is for a choice its entry has not saved or whose choice is not read (rotation-6), is not evaluated, so its formula never warns.
- **Unresolved dice:** while the keyed value's own formula can't be evaluated, the row shows it as unresolved ("Unresolved d6") with its own warning, and no increase as applied: `count` is null, `sources` names only its rows or entry, and the number has no `increases`, since that list holds only increases that add and none adds to dice with no count (fix r2; the output type has no unresolved variant with `increases`). Each increase of its key is still evaluated, as the value is unsuppressed and on the sheet, unless its entry is suppressed or it is for a choice its entry has not saved or whose choice is not read (rotation-6), so an unresolved increase still warns on its own line.
- A conditional extra die, such as Greater Mercy's (only when the target has no condition the paladin's mercies can remove), is not an increase: it stays the feat's Situational Note.

Every combination of a keyed base die (resolved, unresolved, suppressed, absent) and an increase (resolved, unresolved, suppressed, unmatched, repeated, self-targeted) has its case in `src/lib/character-sheet-dice-increase-table.test.ts` (fix r2: 24, what the row shows and which rows warn, or the write's refusal).

Tests: `src/lib/character-sheet-dice-increase.test.ts` (the Cleric 8, copies and an item switched off, no key, two keys, no keyed value whatever the formula, a suppressed increase and a suppressed base, an unresolved increase beside a resolved one, both projections, the schemas and their illegal shapes, a repeated or self-targeted increase, an entry stored before keys), `convex/characterSheetArmorNoneDice.integration.test.ts` (an old one-off reads as before; a Catalog Copy stored before rotation-5, with its provenance, unkeyed dice, a per-day maximum and an `armorAtMost: 'medium'` Modifier, reads and computes exactly as at the rotation's base; the saved sheet; the write paths' refusals).

The sheet shows each one as a chip on its entry's row (`rule-value-chips.tsx`), such as "3d6", or "Unresolved d6", followed by a muted chip per dice increase that added, naming its source. The row is in whichever block holds the entry, for every kind of entry the read counts rule values for (rotation-6 fix r2; `src/components/character-sheet/rule-value-row-coverage.test.tsx` finds every number of the read on its entry's row, kind by kind): Class features for a class feature, Feats & traits for a saved or granted feat or trait, Race for each active race (under the race cards, each under its name, the selected one first: creating a one-off race while a race is selected leaves both active, rotation-6 fix r3) and its racial traits, Archetypes for a selected Archetype (on its card), Sheet entries for a recorded item, Spell Effect or Condition, Personal adjustments for a recorded personal adjustment, and its own section of the Grants list for any other granted entry, whether its definition is the catalog's, a Catalog Copy or a one-off. A Spell's rule values are never counted, so the read gives a Spell none.

Tests: `src/lib/character-sheet-feature-numbers.test.ts` (dice by level, the Ecclesitheurge, two channel classes, an unresolved formula, both projections, the schema and its illegal shapes), `convex/characterSheetRuleValues.integration.test.ts` (the saved sheet for owner, member and outsider), `src/components/character-sheet/character-sheet-grants.test.tsx` (the chip; each increase with its source).

### Damage reduction and spell resistance

`resolveResistances` (`src/lib/character-sheet-resistances.ts`) gives `calculated.damageReduction` and `calculated.spellResistanceStatistic`. Each lists every line of a counting entry, `{ entryId, name, ruleValueIndex, value, applies }` (a damage reduction line also has its `bypass`); `value` is null while its formula can't be evaluated, and such a line never applies.

- **Damage reduction:** the statistic is the highest value per bypass, never a sum (root's default of 2026-11-17), highest first: `values: { bypass, value, entryId }[]`. The line that gives its bypass's value is marked `applies`; of equal lines the first does. A Barbarian 10 Mad Dog lists the Barbarian's 2/— and the Mad Dog's 1/— and has DR 2/—.
- **Spell resistance:** the highest applying line, `value` (null with no line), never a sum. It is the Character's own spell resistance, not the Situation "to overcome spell resistance" (`spellResistance`), which stays a Situation of caster level checks.
- **Conditional lines:** a line whose Situation is not selected goes to `conditional` with its `situation` and never reaches the statistic; selecting the Situation moves it in.
- A Temporary Effect's line (Stoneskin's 10/adamantine) is left out of the permanent projection.

The sheet shows each one in Defenses, under CMD, once the Character has any line of it (`defenses-block.tsx`), as a row like CMD's (`RuleValueRow` in `rule-value-row.tsx`: the label in the body font on the row's solid rule, the statistic right-aligned on it with its dotted underline, "10/adamantine, 2/—"; spell resistance "21"). Beneath the label it lists each line, keyed by its entry and rule value, the one that applies marked "(applies)", and each conditional line with "only when …". It has no breakdown: a rule value is not a Modifier total.

Tests: `src/lib/character-sheet-resistances.test.ts` (Barbarian damage reduction by level, the Mad Dog at 10th, two bypasses, a Temporary Effect, a race and an item, a conditional line and its Situation, an unresolved formula, the schema), `convex/characterSheetRuleValues.integration.test.ts` (a player's feats on the saved sheet), `src/components/character-sheet/defenses-block.test.tsx`.

### Per-day maxima

The owner decided on 2026-11-17 that the sheet shows how many times per day a limited ability can be used: rage rounds, channel energy and lay on hands uses, a ki or arcane pool's points. **The maximum only:** no tally, no uses remaining, no reset, and nothing stores a count.

`resolveDailyMaxima` (`src/lib/character-sheet-feature-numbers.ts`) gives `calculated.dailyMaxima`: one per `dailyMaximum` rule value of a counting entry, except one that joins another (below), `{ entryId, ruleValueIndex, key, unit, value, sources }`, with `floor` and `notCounted` when they apply. The examples in this list are test fixtures (`src/lib/character-sheet-daily-maxima.test.ts`, `src/lib/character-sheet-daily-maxima-floor.test.ts`): the committed Channel Energy, Rage and Extra Channel per-day records are held and give nothing ([Per-day maxima on catalog rows](#per-day-maxima-on-catalog-rows-stats-d3)).

- **Apart per entry and key:** a Cleric 5 / Paladin 4 has its channel uses and its lay on hands uses as two maxima.
- **Increases add per copy:** each counting entry with a `dailyMaximumIncrease` of the same key adds its amount, so two copies of Extra Channel add 4, unless the increase counts once per Source or is for a choice ([Increases](#increases-once-per-source-a-choice-not-counted-rotation-6)). `sources` names the maximum's entry (its counted rows, for a rows amount), then each increase. An increase whose key no maximum has gives nothing.
- **Floored at 0** (rotation-5; root, 2026-11-18: a negative count is not a number of uses, and no rules text is claimed for it): the raw sum, the amount plus every increase, may be below 0; the maximum shown is that sum floored at 0, `max(0, sum)`, once, after the increases. The amount itself may be negative inside the sum, so a Cleric 1 with Charisma 1 and Extra Channel has a raw sum of 3 − 5 + 2 = 0 and channels 0 times, and without the feat a raw sum of −2 and a maximum of 0, not −2. While the floor applies the maximum carries the raw sum as `floor: { sum }` (a calculation field), and its row shows a muted chip beside the maximum, "Floored at 0 (sum −2)": the Cleric without the feat shows "0/day" and that chip; with Extra Channel the sum is 0, nothing is floored, and the row shows "0/day" alone. A clamp in a record's own formula, such as a stated minimum `max(1, …)`, is not this floor: it applies inside the record's amount (the Magus's to its half level alone), before the increases are added, and it stays in the formula. Each key is floored apart.
- **Permanent ability modifiers:** a maximum's or increase's formula reads the permanent ability modifiers, so rage's own +4 Constitution adds no rounds: a Barbarian 4 with Con 14 rages 12 rounds per day, raging or not.
- **Unresolved:** a formula that can't be evaluated, the maximum's or an increase's, gives `value: null` and a rules warning on its entry. Two kinds of increase never do (rotation-6 fix r1): one that is suppressed or for a choice its entry has not saved or whose choice is not read is not evaluated, and an unresolved once-per-Source copy beside a resolved one of its Source is not counted (below), though its formula still warns.
- **Joining maximum** (rotation-6): a maximum with `joins: true` adds its amount to another maximum on the sheet, its host: the first unsuppressed maximum of the same key and unit without `joins`. It is named in the host's `sources` after the host's own, has no maximum of its own and so no chip; it is not an increase, so `oncePerSource` and `choice` do not apply to it. With no unsuppressed maximum of its key and unit without `joins` on the sheet, whatever maxima of other units or keys are, the first joining maximum of its key and unit is the host (rotation-6 fix r6): it is shown as an ordinary maximum and the other joining maxima of its key and unit join it, so one alone is an ordinary maximum and two give one maximum, the first's (`character-sheet-joined-maximum.test.ts`, "two joining maxima with nothing to join"). A suppressed maximum, joining or not, is decided suppressed before its formula is evaluated, so it neither hosts nor joins (rotation-6 fix r1). The floor applies to the joined sum; an unresolved joining maximum leaves the host unresolved; a joining maximum joins only a maximum of its own unit, so beside a host of another unit and none of its own it keeps its own maximum. In the fixtures (`src/lib/character-sheet-joined-maximum.test.ts`), Rage (Cleric) gives the cleric level in rounds and joins the Barbarian's Rage: a Barbarian 8 / Cleric 8 with Constitution 14 shows 4 + 2 + 14 + 8 = 28 rounds on the Barbarian's row, and a Cleric 8 alone 8 rounds on its own row. No committed record carries `joins`.

The sheet shows each one as a chip on its entry's row (`rule-value-chips.tsx`), such as "5/day", "12 rounds/day" or "Unresolved points/day", with no control to spend a use. The row is in whichever block holds the entry, for every kind of entry the read counts rule values for (rotation-6 fix r2; `src/components/character-sheet/rule-value-row-coverage.test.tsx` finds every number of the read on its entry's row, kind by kind): Class features for a class feature, Feats & traits for a saved or granted feat or trait, Race for each active race (under the race cards, each under its name, the selected one first: creating a one-off race while a race is selected leaves both active, rotation-6 fix r3) and its racial traits, Archetypes for a selected Archetype (on its card), Sheet entries for a recorded item, Spell Effect or Condition, Personal adjustments for a recorded personal adjustment, and its own section of the Grants list for any other granted entry, whether its definition is the catalog's, a Catalog Copy or a one-off. A Spell's rule values are never counted, so the read gives a Spell none. The committed checked per-day maxima are on class features: the chips of the nine checked ones and of the Magus's Arcane Pool are on Class features rows; Extra Arcane Pool, a checked feat, gives an increase and no maximum, so the calculation adds its 2 points to the pool's maximum and records the feat among that maximum's sources, and the chip on the pool's row shows the total; a player's one-off feat with a `dailyMaximum` is on Feats & traits (`convex/characterSheetSpeedMaxima.integration.test.ts`).

Tests: `src/lib/character-sheet-daily-maxima.test.ts` (rage by level and Constitution, rage's own Constitution, Extra Channel copies, two classes, an unresolved maximum and increase, the schema and its illegal shapes), `src/lib/character-sheet-daily-maxima-floor.test.ts` (the floor: the Cleric 1 with and without Extra Channel, a positive total, a formula's own minimum, two keys), `convex/characterSheetSpeedMaxima.integration.test.ts` (the saved sheet for owner, member and outsider; the write paths' refusals), `src/components/character-sheet/character-sheet-grants.test.tsx` (the maximum's chip and the floor's).

### Increases: once per Source, a choice, not counted (rotation-6)

Both increase kinds, `dailyMaximumIncrease` and `diceIncrease`, may carry two fields. No committed record carries either, so every committed increase adds per copy as before; the examples here are test fixtures.

- **Once per Source** (`oncePerSource: true`; opt-in by root's decision of 2026-11-20, so an increase without it adds per copy as before): among the active increases of one kind and one key that carry it, that the choice gate (below) does not leave out, and that share a Source (the entry's `sourceKey`, else its rule identity, as [stacking](stacking.md) uses, so a Catalog Copy keeps its original's), the largest resolved one is picked, the first of equal ones, and it adds only when the receiving maximum's or dice's own amount resolves; the others, resolved or not, are not counted. Per-day increases and dice increases are grouped apart (rotation-6 fix r6), so a Source's marked per-day increase and its marked dice increase of one key each count: in a fixture, two copies of a feat carrying both give a Cleric 1 with Charisma 14 3 + 2 + 2 = 7 uses and 1d6 + 2d6 = 3d6, each number listing the second copy as not counted (`src/lib/character-sheet-increase-choice.test.ts`) (rotation-6 fix r1: an unresolved copy beside a resolved one of its Source no longer leaves the maximum unresolved; its formula still warns). With every copy of a Source unresolved, the first counts and the others are not counted, and the two kinds then differ (rotation-6 fix r2): a per-day maximum is unresolved, since one of them adds and none has a number; for dice an unresolved once-per-Source group adds no dice; a resolved base still receives the other increases that count under the usual rules (once per Source where marked; in a fixture a 1d6 base with an independent +2d6 gives 3d6, and beside two copies of another once-per-Source Source only one of them adds, fix r4), and each copy warns on its own line (all in `src/lib/character-sheet-increase-once-per-source.test.ts`). An increase without the field is in no such group, even beside one of the same Source that carries it, and an unresolved one leaves a per-day maximum unresolved and adds no dice, as before. In the fixtures, two Bracelets of Mercy carrying it give a Paladin 4 with Charisma 10 2 + 1 = 3 uses, not 4; two copies of an Extra-Performance-like feat without it give a Bard 3 8 + 6 + 6 = 20 rounds (`src/lib/character-sheet-increase-once-per-source.test.ts`).
- **For a choice** (`choice`: the reviewed options the increase is for): it adds only while its entry has a saved choice that matches an option, trimmed and case-insensitively, as the sheet compares a feat's choice in its duplicate check and prerequisites. A blank choice is none. Which entries' choices the gate reads is decided when the sheet is calculated, not when the rule value is written (root, 2026-11-20; rotation-6 fix r3): nothing about the entry's kind is checked at any write path, so the field is accepted on any kind, with the shape above. The gate reads a choice only where the sheet recorded one as text before rotation-6, in its row's own editor: a saved feat's or trait's (the Selection editor), a class feature's, a racial trait's, a granted feat's or trait's and a granted personal adjustment's (the grant row's editor), and a selected Archetype's (its card's editor). It reads no other entry's choice, so on every other entry an increase for a choice is never counted, whatever the entry saves, since no choice saved there can affect the increase (rotation-6 fix r4): the race (it saves its race equivalence, a Rule Identity, or its weapon proficiency choice, text typed in the Proficiencies editor; left out by root's decision), a recorded personal adjustment (no choice control; the Selection writer can save a choice in its state), an item, a Spell Effect and a Condition (they save no choice of their own: their writers refuse one; an item's abilities may each save one, such as Bane's designated foe, which is read only for the ability; rotation-6 fix r5), and an entry whose control saves a structured value: a class-skill trait's class skill (its control saves the skill's name, and the sheet also reads a skill key or abbreviation there, `traitClassSkillChoice`, so a comparison of text would be ambiguous), a race equivalence's Rule Identity and a racial trait's ability score (no names). With no choice or another one it adds nothing, is not evaluated, so its formula never warns (rotation-6 fix r1), and takes no part in `oncePerSource`. In the fixtures, Extra Channel's increase for `['Cleric']` gives a Cleric 1 with Charisma 14 3 + 2 + 2 = 7 uses once the feat's choice is "cleric", and 5 without; an Extra-Rage-like record with one output per pool (`['Rage', 'Barbarian']` and `['Bloodrage', 'Bloodrager']`) raises only the chosen pool (`src/lib/character-sheet-increase-choice.test.ts`); each kind whose choice is read or not is in `src/lib/character-sheet-increase-choice-recording.test.ts`.
- **Warnings:** an unsuppressed increase left out for its choice, on an entry whose choice is read, warns on its entry while a number of its own kind and key receives it (rotation-6 fix r6): a per-day increase while an unsuppressed per-day maximum of its key, in any unit, is on the sheet, a dice increase while an unsuppressed keyed dice value of its key is. It warns once per entry, naming the options of every such increase, two lists of the same options in another order, case or spacing once (rotation-6 fix r1 and r5): `ruleValueChoiceMissing` (incomplete, so it can't be accepted) with no choice saved, "Extra Channel’s increase is not counted until its choice is recorded; it is for the choice Cleric."; `ruleValueChoiceUnmatched` (a rules warning, which can be accepted) when none of the entry's increases is for its choice, "Extra Channel’s increase is not counted for its choice, Paladin; it is for the choice Cleric.". When the entry has more than one such increase the message says "increases are", counting the increases, not their lists (rotation-6 fix r6): "each is for the choice Cleric" when their options are the same, and otherwise it names each list once with how many of the increases it is for (rotation-6 fix r7): "one is for the choice Rage or Barbarian and one for Bloodrage or Bloodrager", "two are for the choice Cleric and one for Oracle", "one is for the choice Cleric, one for Oracle and one for Shaman". The message speaks of the increase, not the entry, since another output of the entry may still add, and names what the increase is for without promising that it then counts, since with that choice saved an increase whose formula can't be evaluated still adds nothing and warns for its formula (rotation-6 fix r2). Only an entry whose choice is read warns (rotation-6 fix r3): its row shows the warning, and its choice is recorded in that row's own editor (`rule-value-row-coverage.test.tsx` records it in the editor of a racial trait, a selected Archetype, a class feature, a saved feat, a saved trait, a granted feat, a granted trait and a granted personal adjustment, each kind whose choice is read, and reads the sheet; rotation-6 fix r4 added the three granted ones). An entry whose choice is not read warns nothing, since no choice it could save would count the increase; its increase's line says why. An entry whose choice picks one of its outputs does not warn for the others. With no number of its kind and key on the sheet, such as a per-day increase beside dice of its key alone or a dice increase beside a per-day maximum alone, it raises no choice warning and no line. An accepted `ruleValueChoiceUnmatched` covers the saved choice and the options it names: it reopens when another choice is saved or an option is named or no longer named, as when a pool one of the entry's increases is for comes onto the sheet or leaves it; their order, their case and spaces around them change nothing (rotation-6 fix r4, `character-sheet-increase-choice.test.ts` and `convex/characterSheetIncreaseRules.integration.test.ts`).
- **Not counted:** each per-day maximum lists the per-day increases of its key, and each dice number the dice increases of its key, not counted for their Source or their choice in `notCounted` (rotation-6 fix r6: an increase of the other kind is never on its list), present only when there is one: `{ entryId, name, reason: 'sameSource', counted }` (`counted` names the increase that counts; a copy not counted is listed resolved or not), `{ entryId, name, reason: 'noChoice' }` or `{ entryId, name, reason: 'otherChoice', choice }` (the saved choice, trimmed) for an entry whose choice is read, and `{ entryId, name, reason: 'choiceNotRead' }` for one whose choice is not read (rotation-6 fix r3). An unresolved increase that counts is not listed: it leaves the maximum unresolved, or adds no dice, and has its own warning. Dice list them whether or not their own count resolves. A suppressed entry's increase is never listed (rotation-6 fix r1: decided before its formula). The row shows each as a muted chip beside the maximum or dice (`rule-value-chips.tsx`), on every row kind above ([Dice](#dice)), one chip per line even when one entry gives two: "Bracelet of Mercy not counted: copies don’t stack", or, when the counted one has another name, "My bracelet not counted: doesn’t stack with Bracelet of Mercy"; "Extra Channel not counted: no choice recorded"; "Extra Channel not counted: chosen for Paladin"; and, for a recorded personal adjustment in a test fixture, "Pool boost never counted: its choice can’t affect this increase" (rotation-6 fix r4: the words are true of every entry whose choice is not read, the race's saved weapon proficiency choice included).

**What a curator writes.** `oncePerSource: true` on an increase whose text gives one effect however many copies are worn or taken (an item's), and no field where the text says its effects stack; `choice` listing each name the entry's choice may be saved as, one output per key the choice picks, on an entry whose choice is read (above): the choice is saved as the text typed in the row's editor, trimmed, so `choice` lists that text, such as `['Cleric']` for Extra Channel, in any case; on any other entry the increase is accepted and never counts; `joins: true` on a maximum whose text adds its rounds or uses to another feature's pool. Each needs a reviewed record like any rule value ([Rule-value records](../catalog-import/curation.md#rule-value-records-stats-d1)).

Each listed reward names its class, its races, the fraction one selection gives and its PCGen source line. The list holds five of the nine Advanced Player's Guide rewards in the release scope that change a per-day number (`tests/catalog/favored-class-rewards.test.ts` checks each against its inventory row and PCGen line):

| ------------------------ | --------- | --------------- | ------------------------------------------------------- | ------------------------------ |
| `bardicPerformanceRound` | Bard      | Gnome, Half-Elf | 1 round                                                 | 142                            |
| `bomb`                   | Alchemist | Gnome           | 1/2 bomb                                                | 148                            |
| `stunningFist`           | Monk      | Halfling        | 1/2 attempt (its +1 CMD against grapple is not counted) | 162                            |

The four rewards that add to "one power" the character selects at 1st level (the arcane school, bloodline and two domain power rewards, lines 135, 144, 150 and 168) are left out by this slice: the stored choice names no power, so a count could feed every such power a character has, both of a Cleric's domains for one.

- **The count:** a reviewed rule value's formula reads `@favoredClassReward.<id>`, the number of Class Levels that chose the reward and count. A level counts when its class is the reward's class (an Unchained Class's levels count as the original's, as for the favored class: [Unchained classes](unchained-classes.md)), that class is a favored class, and the character counts as one of the reward's races: an active race's rule identity, or a race the stored `countsAsRaces` of a counting entry names (the sheet's `racial.countsAsRaces`), so a Half-Elf's Elf Blood and a Half-Orc's Orc Blood let them take a Human reward, as the Advanced Player's Guide FAQ allows (research decision in issue #225). The variable is a whole number of selections, so a formula applies the fraction itself: `floor(@favoredClassReward.bomb / 2)`. An id the list does not hold makes the formula unresolved.
- **Only in a catalog definition's rule value:** the variable resolves by where a rule value comes from, never by how its entry is named. The formula of a rule value of each of the six kinds (a per-day maximum or its increase, dice or a dice increase, damage reduction, spell resistance) reads the count when its definition is stored with `scope: 'global'` and is not a Catalog Copy (`hasReviewedRuleValues` in `character-sheet.ts`); scope and copy status alone decide. Only the catalog import (`catalogIdentityAllocation`, which stores a bodiless identity) and the end-to-end fixtures write such a definition, and no player's or owner's writer edits one ("Global definitions are read-only"). Its rule values are those of the selected Catalog Release's body for its identity, a definition row or a retirement's retained body (`lastUsableDefinition`), as `candidateDefinition` projects it, when a release is active and holds one; with no active release, or one that neither admits nor retires it, they are the stored definition's own. A definition that is not global, or is a Catalog Copy, keeps the result it had before the count existed, wherever its body comes from, for example a player's or an owner's one-off (`createOneOff`), also once saved to the campaign or edited to a core-rule Condition, a Catalog Copy (`detach`, `customizeForCampaign`, a moved Character's copies), which does not record whether its original was reviewed, a Personal Adjustment (`createPersonalAdjustment`), a sheet entry (`createSheetEntry`), the Character's base scores (Character-scoped, created with the sheet), and a Spell the sheet installs for a Character (`spellCatalogInstall`: Character-scoped and `importedSpell`, so `candidateDefinition` projects its body from the release, yet its scope is not global). Where the sheet evaluates such a definition's rule value, the variable is unsupported there: the rule value gives no number, with its warning; the sheet evaluates no formula of a Spell's, nor a class's or an Item Ability's rule values, so these give no number, as before. A Modifier's formula that the sheet evaluates does not read the variable, a catalog definition's and an Item Ability's included: it gives 0 with `unsupportedFormula`. A Modifier that a core-rule Condition's projection replaces (a one-off Condition saved as Dazzled, or edited to the core-rule Dazzled) is not evaluated and gives no warning. `src/lib/character-sheet-favored-class-reward-provenance.test.ts` is a regression aid for that predicate, not a proof about the schema. Its walk of `convex/schema.ts` compares each table's formula paths, in full, with the 21 it lists (a Modifier value and six rule-value amounts in each of `catalogEntry`, a release's definition rows and a moved Character's definitions) and the schema's untyped fields (`v.any()`) with the 13 it lists, each with what it holds, and fails on a path or field it does not list; it fails in the same way on a definition kind, a Sheet Entry kind or a rule-value kind (`ruleValueSchema`) it does not list. Its matrix calculates each definition kind's listed formula places for each of the definitions above that the test stores of that kind, and for a catalog definition, from fixtures whose shape it checks against the stored validators (without a database, so Convex IDs are checked as strings only and the fixtures' synthetic IDs pass), with an active source that reaches the place (a Racial Trait of the active race, an Archetype of the character's class, an Item Ability on an item, a Class Level's class). It runs three formulas through the calculator at each place: a supported variable, the control, which gives its number, or, where the sheet evaluates nothing, the result of no formula there; the count's variable, with no reward chosen, which gives the result of the third, a variable no version of the sheet supports (and, where the sheet evaluates nothing, the result of no formula), except in a catalog definition's rule value the sheet evaluates, where the count's variable gives 0 and the third is not run. A retirement's retained body, inside the listed report payload, runs through `candidateDefinition` before the calculator: for a feat, a trait and a class feature, the catalog definition's rule values then read the count and its Modifier gives the result it had before the count existed, and a campaign's Catalog Copy of a retained feat keeps its stored body.
- **Not counted:** a chosen reward that does not count adds 0, and its level has the rules warning `favoredClassRewardNotCounted`, naming the level and why: "Level 2: +1 round of bardic performance per day isn’t counted: this level’s class isn’t Bard and isn’t one of your favored classes." A reward id the list no longer holds counts 0, and the same check says the sheet no longer lists it. An accepted warning stays accepted while the facts its fingerprint holds stay the same: for a listed reward, the reward, why it isn't counted, the level's class, whether that class is favored and the races the character counts as; for an id the list does not hold, that id alone (no class, favored class or race can make it count), so it stays accepted while that id stays saved on that level. When the level's choice or one of those facts changes, the warning clears if the level's reward now counts or the level no longer chooses a reward (a hit point, a skill rank, a note or nothing), and otherwise shows again, not accepted: another id, listed or not, that does not count, or the same listed reward still not counted under changed facts.
- **Saving:** `editClassLevel` refuses an id the list does not hold ("Choose a favored class reward from the list") and saves a listed reward whose class or race does not fit, as it saves a hit point on a class that isn't favored; the warning says so.

No committed record's formula reads the count yet, so no number on any sheet changes: the examples are test fixtures (`src/lib/character-sheet-favored-class-rewards.test.ts`: a Gnome Bard with one and three selections, a Human Bard, a multiclass Gnome, a Bard that isn't favored, a Gnome Alchemist with one to three reward selections, an Unchained Monk, a Half-Elf and a Half-Orc Monk with four ki selections, a Half-Orc Barbarian, a Human and a Half-Elf Alchemist, the warning's fingerprint, a Personal Adjustment's, a one-off's and a catalog Modifier's formula; `convex/characterSheetFavoredClassRewards.integration.test.ts`: the write path, its refusal, Class Levels stored before rewards existed, the count through the read, a Personal Adjustment saved through its writer, and a one-off Condition saved as Dazzled or edited to a core-rule Condition).

**The release-scope boundary (maxima-promote-1 fix r1; root, 2026-11-20).** A per-day maximum is promoted only if the number it shows is right for every character that can be built from the release scopes (`campaign-mvp-v1` and the party scope; the `--pcgen` preview is not built from): a release-scope row that changes the count is bound exactly by a record, two copies included, or the maximum is held. The pin is over what the scope reader the import uses yields, not over the file's bytes (fix r15): of what `readReleaseScope` yields for `campaign-mvp-v1` and `resolvePartyReleaseScope` for the party scope, it takes the favored-class reward contracts (channel "racial favored class", or an ID under `rule/core/favored-class/`) and the rows that refer to them (a key that is a selected contract's ID or under that prefix), each list as yielded, in its order, nothing deduplicated, and holds one digest per scope of those two lists in a reviewed list ([`rule-values-boundary-rewards.json`](../../tests/catalog/rule-values-boundary-rewards.json)); beside it, per reward, the review's reading (the race and class combinations it admits and the per-day keys it changes), joined by reward ID after the digest is compared. It fails when a scope's keys differ from the pinned ones as lists, the same keys the same number of times, naming every key whose count differs, added, removed or changed, with its pinned and current count (fix r5; the launch scope's import keys cannot repeat, the party scope's schema does not forbid it), so that each added row is reviewed against every such maximum before the pin is updated; when a listed row is listed for no scope or is no longer in its scope; when a record has two per-day maximum outputs of one key (no committed record has two maxima at all, so the shape is forbidden outright); when a checked record's per-day maximum outputs and their entries differ as multisets, or an entry is repeated or names a record or an output that no longer exists; and when a listed row is bound by a record that does not exist, or that is drafted while the maximum is checked.
